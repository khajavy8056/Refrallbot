# امنیت

## پیاده‌سازی‌شده

| موضوع | روش |
|---|---|
| رمز مدیران | `password_hash` با الگوریتم پیش‌فرض PHP (bcrypt/argon2) |
| سشن | کوکی `HttpOnly`، `SameSite=Lax`، `Secure` در HTTPS، تجدید شناسه پس از ورود |
| CSRF | توکن per-session در تمام فرم‌های POST + هدر `X-CSRF-Token` برای AJAX |
| SQL Injection | فقط prepared statement با پارامتر نام‌دار؛ نام جدول/ستون از allowlist |
| XSS | همه خروجی‌ها با `e()` escape می‌شوند؛ JSON با `JSON_HEX_TAG` |
| دسترسی | Middleware نقش/مجوز برای هر مسیر `/admin/*` |
| راز تلگرام | توکن و شماره کارت با AES-256-GCM (`v1:` prefix، nonce تصادفی) |
| Webhook | مقایسه `X-Telegram-Bot-Api-Secret-Token` با `hash_equals` |
| Mini App | امضای HMAC `initData` + انقضای ۲۴ ساعته |
| قفل ورود | حداکثر ۵ تلاش در بازه ۱۵ دقیقه، بر اساس username+IP |
| هدرها | `X-Frame-Options: SAMEORIGIN`, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`, `HSTS` در حالت HTTPS |
| فایل‌ها | `storage/` باید بیرون از docroot یا با `.htaccess` مسدود شود (در `docs/INSTALL.md` توضیح داده شده) |
| خطا | در حالت production فقط پیام عمومی؛ جزئیات در `storage/logs` |

## ورودی‌های اعتبارسنجی‌شده

- شماره کارت: ۱۶ رقم + الگوریتم لان
- شماره تماس: قالب ایرانی/بین‌المللی
- مبالغ: عدد صحیح تومان، بدون اعشار، حداقل/حداکثر
- شناسه تلگرام: عدد صحیح مثبت
- متن پیام همگانی: محدودیت طول، پاک‌سازی تگ HTML (`parse_mode` کنترل‌شده)

## کنترل تقلب

| سیگنال | آستانه پیش‌فرض | اثر |
|---|---|---|
| IP مشترک برای چند ثبت‌نام | ۳ | افزایش امتیاز ریسک |
| ثبت‌نام انبوه در بازه کوتاه | ۱۰ | رویداد امنیتی |
| دعوت انبوه توسط یک معرف | ۱۵ | علامت‌گذاری |
| استفاده مجدد شماره کارت | ۲ کاربر | `card_reuse` + بررسی دستی |
| کاربران بلاک‌شده/حذف‌شده | — | حذف از پرداخت پورسانت |

امتیاز ریسک در `users.risk_score` نگه داشته می‌شود؛ عبور از آستانه (`risk_mark_threshold`، پیش‌فرض ۴۵) کاربر را «مشکوک» می‌کند.

## نکات عملیاتی

1. `APP_DEBUG=false` در production.
2. `APP_KEY` را عوض نکنید — با تغییر آن، توکن ربات و شماره کارت‌های ذخیره‌شده غیرقابل رمزگشایی می‌شوند.
3. `.env` را از مخزن و از دسترس وب خارج نگه دارید (`chmod 640`).
4. `storage/` را مرتب پشتیبان بگیرید؛ `storage/installed.lock` را حذف نکنید.
5. به‌جای `admin` ساده، نام کاربری غیرقابل‌حدس انتخاب کنید و ورود پنل را در صورت امکان با IP محدود کنید.
6. توکن ربات را هر چند ماه با `/revoke` در BotFather بچرخانید.

## آنچه پیاده نشده

- آپلود فایل/تصویر (در این نسخه هیچ مسیر آپلودی وجود ندارد)
- احراز هویت دوعاملی (2FA) برای مدیران
- سیاست CSP سخت‌گیرانه (فقط هدرهای پایه ارسال می‌شود)
- شماره شبا (فقط کارت بانکی پشتیبانی می‌شود)
- محدودیت نرخ در سطح وب‌سرور (باید در Nginx/Apache یا Cloudflare تنظیم شود)
- امضای دیجیتال پشتیبان
- لاگ تغییرات در سطح دیتابیس (فقط سطح اپلیکیشن)
