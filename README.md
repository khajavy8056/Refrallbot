# رفرال‌بات — سامانه مدیریت بازاریابی ارجاعی تلگرام

سامانه‌ی کامل و آماده‌ی بهره‌برداری برای مدیریت **کمپین دعوت دوستان (Referral)** روی تلگرام، با پورسانت چندلایه، کیف پول دقیق، برداشت با کارت بانکی، پنل مدیریت وب و پنل کاربری Mini App.

نوشته‌شده با **PHP 8.1+** و **MySQL/MariaDB**، بدون هیچ فریم‌ورک یا وابستگی خارجی (بدون Composer)، طراحی‌شده برای **هاست اشتراکی**: فقط Webhook + Cron.

## پیش‌نیازها

- PHP **8.1** یا بالاتر (تست‌شده تا 8.3)
- افزونه‌های PHP: `pdo`, `pdo_mysql`, `mbstring`, `openssl`, `curl`, `json`
- MySQL 5.7+/MariaDB 10.3+ (یا SQLite فقط برای تست/توسعه)
- دسترسی به Cron (cPanel یا مشابه)
- دسترسی به دکمه `Webhook` تلگرام → **نیاز به HTTPS معتبر** (پایین را بخوانید)

## نصب روی هاست اشتراکی — تک‌فایل `install.php`

**بدون SSH، بدون Composer، بدون خط فرمان.** فقط سه کار:

۱) **آپلود** کل پوشه‌ی پروژه در هاست (مثلاً در `public_html/` یا `public_html/bot/`).

۲) در cPanel → *MySQL Databases* یک **پایگاه داده** و یک **کاربر** بسازید و کاربر را با دسترسی
`ALL PRIVILEGES` به دیتابیس وصل کنید.
اگر این کار را نمی‌کنید، در همان ویزارد تیک «اگر پایگاه داده وجود نداشت، خودش بسازد» را بزنید
(فقط وقتی کاربر MySQL اجازه‌ی `CREATE` داشته باشد کار می‌کند).

۳) در مرورگر باز کنید:

```
https://YOUR-DOMAIN/install.php
```

> اگر هاست شما docroot را روی پوشه‌ی `public/` تنظیم کرده است، آدرس `https://YOUR-DOMAIN/install.php`
> هم همان ویزارد را باز می‌کند (`public/install.php`). آدرس `/install` هم به همین صفحه می‌رسد.

ویزارد شش مرحله دارد و همه‌چیز را خودش انجام می‌دهد:

| مرحله | چه می‌کند |
|---|---|
| ۱ | بررسی نیازمندی‌ها (PHP ≥ 8.1، PDO MySQL، mbstring، OpenSSL، دسترسی نوشتن `storage/`) |
| ۲ | اتصال به MySQL — با دکمه‌ی **«فقط آزمایش اتصال»** و گزینه‌ی **ساخت خودکار دیتابیس**. اگر دیتابیس قبلاً نصب شده باشد هشدار می‌دهد |
| ۳ | ساخت ۲۵+ جدول (قابل تکرار، داده‌ها را پاک نمی‌کند) |
| ۴ | ساخت **اولین مدیر کل**: نام، نام کاربری و رمز (حداقل ۱۰ کاراکتر، حروف بزرگ/کوچک/عدد — هیچ رمز پیش‌فرضی وجود ندارد) |
| ۵ | نام سامانه، آدرس پایه، **زیرپوشه نصب (خودکار تشخیص داده می‌شود)**، **مبلغ پاداش هر معرفی**، **حداقل مبلغ برداشت**، و حالت **پنل وب (Mini App)** |
| ۶ | نوشتن `.env` (شامل `APP_KEY` تصادفی و `APP_BASE_PATH`)، ساخت `.htaccess` محافظ، قفل دائمی ویزارد |

پس از پایان، ویزارد برای همیشه قفل می‌شود (`storage/installed.lock` + کلید `installed_at`)
و مستقیم به `‎/admin/login` هدایت می‌شوید.

### نصب بدون دامنه (فقط با IP)

هیچ مشکلی نیست — پنل مدیریت یک وب‌اپ معمولی روی HTTP است و کامل کار می‌کند:

```
http://SERVER-IP:PORT/admin      (اگر docroot روی public/ است)
http://SERVER-IP:PORT/public/    (اگر کل پروژه در docroot است)
```

در این حالت در مرحله‌ی ۵، حالت پنل وب کاربران **خودکار خاموش** می‌شود (تلگرام برای Mini App
الزاماً HTTPS می‌خواهد) و کاربران همه‌ی کارها را با **دکمه‌های داخل ربات** انجام می‌دهند:
حساب، دعوت، معرف‌ها، درآمد، کیف پول، برداشت، تاریخچه، جشنواره‌ها، رتبه‌بندی، اعلان‌ها، پشتیبانی، راهنما.
بعداً که دامنه + SSL گرفتید، از **پنل مدیریت → تنظیمات → شرایط ورود** پنل وب را روشن کنید.

## اتصال ربات تلگرام

۱) در تلگرام به [@BotFather](https://t.me/BotFather) بروید → `/newbot` → توکن را بردارید.
۲) پنل مدیریت → **اتصال به ربات** → توکن را وارد کنید → «ذخیره و تست توکن».
   - توکن با AES-256-GCM ذخیره می‌شود و کامل نمایش داده نمی‌شود.
۳) آدرس Webhook پیشنهادی را بررسی کنید (باید `https://` معتبر باشد) → «تنظیم Webhook».
۴) «همگام‌سازی منوها و دستورات» را بزنید تا `start/menu/help` و دکمه Mini App روی ربات ثبت شود.
۵) اگر می‌خواهید عضویت کانال اجباری شود: ربات را **مدیر کانال** کنید، سپس در بخش «کانال‌های اجباری» کانال را اضافه و «بررسی سلامت» را اجرا کنید.

> ⚠️ اگر ربات مدیر کانال نباشد، تلگرام خطا برمی‌گرداند. سامانه این خطا را **به‌درستی از «کاربر عضو نیست» تفکیک می‌کند** و آن را در رویدادهای امنیتی ثبت می‌کند.

## دسترسی به پنل مدیریت با IP و پورت

پنل مدیریت یک وب‌اپ معمولی است و **بدون دامنه و بدون SSL هم کار می‌کند**:

```
http://SERVER-IP:PORT/admin
http://SERVER-IP/refrallbot/admin     (در صورت نصب در زیرپوشه)
```

اگر از سرور محلی استفاده می‌کنید:

```bash
php -S 0.0.0.0:8080 -t public public/index.php
# سپس: http://SERVER-IP:8080/admin
```

تنها کاری که لازم است: مقدار `APP_BASE_PATH` را در `.env` در صورت نصب در زیرپوشه تنظیم کنید.

## فعال‌سازی پنل کاربری (Mini App)

Mini App **به‌صورت فنی نیازمند HTTPS معتبر** است؛ تلگرام آدرس `http://` یا گواهی خودامضا را نمی‌پذیرد.

مسیرهای ممکن:

1. **دامنه + گواهی رایگان** (Let's Encrypt یا SSL خودکار cPanel) → بهترین حالت.
2. **سرویس‌های تونل موقت** برای تست (مثل Cloudflare Tunnel / ngrok) — برای محیط عملیاتی توصیه نمی‌شود چون وابسته به سرویس سوم است.
3. **بدون HTTPS**: پنل مدیریت کامل کار می‌کند، ربات هم با روش **Polling دستی** (اجرای `bin/poll.php` از Cron) می‌تواند پیام بگیرد، اما **Mini App و Webhook کار نمی‌کنند**.

پس از تأمین HTTPS:

1. در `.env`: `APP_URL=https://your-domain.com`
2. پنل → اتصال به ربات → «آدرس پایه سامانه» را وارد کنید
3. «تنظیم Webhook» و سپس «همگام‌سازی منوها» (دکمه Mini App روی `https://your-domain.com/app` تنظیم می‌شود)

## Cron

### راه ۱ — بدون دسترسی به crontab (رایج‌ترین حالت هاست اشتراکی)

پنل مدیریت → **اتصال به ربات** → بخش **«کرون وب»** یک آدرس آماده با توکن نشان می‌دهد:

```
https://YOUR-DOMAIN/cron/run?token=TOKEN&task=all
```

همین آدرس را در «Cron Jobs» کنترل پنل هاست یا هر سرویس زمان‌بندی رایگان هر ۵ دقیقه صدا بزنید.
توکن ۴۸ کاراکتری تصادفی است، در دیتابیس ذخیره می‌شود و با `hash_equals` مقایسه می‌شود؛
بدون توکن پاسخ `403` و JSON خطا برمی‌گردد و هیچ کاری اجرا نمی‌شود.

| پارامتر | مقدار |
|---|---|
| `token` | توکن امن (از پنل کپی کنید) |
| `task` | `all` (پیش‌فرض) / `broadcast` / `campaigns` / `maintenance` / `backup` / `security` |

### راه ۲ — با دسترسی به crontab

```bash
# ارسال همگانی — هر ۲ دقیقه
*/2 * * * * /usr/local/bin/php /home/USER/refrallbot/bin/cron.php broadcast --quiet

# جوایز کمپین، نگهداری، امنیت و پشتیبان — هر ۱۰ دقیقه
0,10,20,30,40,50 * * * * /usr/local/bin/php /home/USER/refrallbot/bin/cron.php all --quiet
```

برای دیدن دستور دقیق با مسیر صحیح: `php bin/install-cron.php`

اگر Webhook ممکن نیست (بدون HTTPS)، از Polling دستی استفاده کنید:

```bash
* * * * * /usr/local/bin/php /home/USER/refrallbot/bin/poll.php --quiet
```

## تست‌ها

۱۱ سناریوی تست + ۳ تست تکمیلی (رندر قالب‌ها، دود مسیرها، دود عملیات پنل)، **۴۴۵ بررسی**، بدون وابستگی خارجی:

```bash
php tests/run_all.php
```

| فایل | موضوع | تعداد بررسی |
|---|---|---|
| `01_setup_test.php` | Migration و ساختار دیتابیس | 11 |
| `02_referral_test.php` | ثبت‌نام، معرف، لینک اختصاصی | 25 |
| `03_multilevel_test.php` | پورسانت ۸ لایه و نسخه‌بندی تنظیمات | 27 |
| `04_withdrawal_test.php` | برداشت، رزرو، تأیید/رد/پرداخت | 44 |
| `05_bot_webhook_test.php` | ربات، Webhook، خطای API و عضویت کانال | 22 |
| `06_miniapp_auth_test.php` | امضای initData، سشن Mini App، CSRF، XSS | 31 |
| `07_admin_security_test.php` | ورود مدیر، قفل تلاش، لاگ، SQLi، تقلب، جعل IP | 50 |
| `08_broadcast_campaign_test.php` | پیام همگانی، گروه‌بندی، جشنواره و جایزه | 33 |
| `09_installer_settings_test.php` | نصب، تنظیمات قابل تغییر، پول، رازها | 46 |
| `10_e2e_integrity_test.php` | سناریوی کامل و صحت دفتر مالی | 37 |
| `11_miniapp_e2e_test.php` | احراز هویت initData و همه APIهای پنل کاربری | 39 |

| `13_installer_flow_test.php` | ویزارد نصب: نیازمندی‌ها، مدیر، پاداش، قفل نصب، `install.php`، زیرپوشه | 63 |
| `14_web_cron_test.php` | کرون وب: توکن، طبقه‌بندی وظایف، رد درخواست بدون/با توکن غلط، عدم نشت خطا | 32 |

| `_smoke.php` | رندر ۱۹ قالب HTML بدون هشدار PHP | ۱۹ قالب |

جمع: **۴۸۶ بررسی در ۱۴ سناریو + ۸۲ بررسی تکمیلی (مسیرها و عملیات) = ۵۶۸ بررسی** به‌همراه رندر ۱۹ قالب، **۰ شکست** (آخرین اجرا: PHP 8.3).

GitHub Actions (فایل **`.github/workflows/tests.yml`** — فعال) این تست‌ها را روی PHP 8.1/8.2/8.3 اجرا می‌کند،
سینتکس همه فایل‌ها و ارجاع کلاس‌ها را بررسی می‌کند (`_lint.php`)، یک تست دود روی سرور واقعی PHP می‌زند
(`/healthz`, `/admin` → 302، `/install` و `/install.php` → 403، کرون وب بدون توکن → 403 و با توکن → 200،
assets، مسدود بودن `.env` و `src/`) و مخزن را برای وجود راز اسکن می‌کند.

> سه Job: `php-tests` (ماتریس ۸.۱/۸.۲/۸.۳)، `http-smoke`، و `security-scan`.
> جزئیات در [`docs/CI-SETUP.md`](docs/CI-SETUP.md). تست‌ها بدون CI هم کاملاً قابل اجرا هستند.

```bash
php tests/run_all.php      # همه سناریوها + تکمیلی‌ها
php tests/_lint.php        # فقط بررسی سینتکس
php tests/_route.php       # فقط دود مسیرها
php tests/_actions.php     # فقط دود عملیات پنل
```

## محدودیت‌های واقعی

صادقانه و بدون اغراق:

1. **Webhook و Mini App به HTTPS معتبر نیاز دارند.** این محدودیت تلگرام است، نه سامانه. روی IP بدون SSL، پنل مدیریت کامل کار می‌کند اما ربات پیام دریافت نمی‌کند (مگر با Polling دستی).
2. **بدون Worker همیشگی**: ارسال همگانی مرحله‌ای انجام می‌شود (۲۵ پیام در هر اجرا). با Cron هر ۲ دقیقه، برای ۱۰٬۰۰۰ کاربر حدود ۱۳ ساعت زمان لازم است. برای حجم بالاتر باید Cron را دقیق‌تر کنید.
3. **بدون درگاه پرداخت**: برداشت‌ها دستی توسط مدیر ثبت می‌شود (`paid` + کد پیگیری). هیچ اتصال خودکار به بانک/شتاب وجود ندارد.
4. **MySQL اجرا نشده است**: تست‌ها روی SQLite اجرا می‌شوند. کد از PDO استاندارد استفاده می‌کند و کوئری‌ها برای MySQL نوشته شده‌اند، اما تست واقعی روی سرور MySQL در این محیط انجام نشده و باید پس از نصب بررسی شود.
5. **تست دود HTTP فقط در GitHub Actions اجرا می‌شود**: در محیط ساخت این پروژه، PHP CLI و سرور وب در دسترس نبود؛ بنابراین `_seed_http.php` + `php -S` (job `http-smoke`) برای اجرای واقعی HTTP نوشته شده و در CI اجرا می‌شود. تست‌های `_route.php` و `_actions.php` همان مسیرها را درون‌فرایندی (Router + کنترلر واقعی) پوشش می‌دهند.
6. **تماس با API تلگرام در تست‌ها شبیه‌سازی شده است** (بدون توکن واقعی). رفتار واقعی Telegram API نیازمند توکن واقعی است.
7. **پشتیبان‌گیری داخلی برای دیتابیس‌های بزرگ مناسب نیست**؛ از `mysqldump` هاست استفاده کنید.
8. **Mini App از داخل تلگرام باز می‌شود**؛ باز کردن `/app` در مرورگر معمولی پیام «دسترسی از داخل تلگرام لازم است» می‌دهد (به‌دلیل امضای initData).
